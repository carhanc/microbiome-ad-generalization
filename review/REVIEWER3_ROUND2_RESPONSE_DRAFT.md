# Response to Reviewer 3 — Round 2

**Manuscript:** "Cross-Cohort Generalization Failure in Gut Microbiome-Based Alzheimer's Disease Classifiers: Evidence from Five Independent Cohorts with Batch Correction Analysis"
**Status:** Internal draft. Not submitted anywhere.
**Companion documents:** `audit/REVIEWER3_ROUND2_PREAUDIT_2026-09-12.md` (pre-audit establishing the pre-fix state), `audit/REVIEWER3_ROUND2_IMPLEMENTATION_LOG_2026-09-12.md` (every change, command, and number), `audit/REVIEWER3_ROUND2_FINAL_VALIDATION_2026-09-12.md` (final validation report).

We thank the reviewer for these five concerns. All five identified genuine methodological gaps, and addressing them changed our results and conclusions in ways we report below without qualification or minimization — in one case (batch correction) substantially reversing a previously reported mechanistic claim, and in another (the Jaccard null) reversing a significance conclusion in the opposite direction (from non-significant to significant). We agree with all five concerns.

## Concern #1

> The feature/genus set used in supervised cross-cohort analyses appears to have been defined using all cohorts, including the held-out cohort. They request a training-only feature-selection sensitivity analysis.

**We agree.** Our pre-audit reproduced the checked-in 396-genus matrix directly from the git-tracked pre-filter per-cohort tables and confirmed it was generated by a global ≥20%-prevalence filter applied across all five cohorts simultaneously — not by the rule the manuscript had stated (≥1 count in ≥2 samples, which we confirmed would instead yield 876 genera). The reviewer is correct that this is a global, not training-only, design: the held-out cohort's own prevalence contributed to deciding which 396 of ~1,500+ raw genera existed as features at all, for every LOCO and pairwise experiment.

**Exact analysis/code change:** New script `scripts/09_training_only_feature_sensitivity.py`. For every within-cohort outer fold, every LOCO hold-out, and every pairwise train cohort, the ≥20%-prevalence filter is re-derived from scratch using only that split's training-side AD/CN-labeled samples; held-out/test samples are projected onto the training-derived genus set (absent genera filled with zero), and zero-replacement + CLR are applied per-sample after projection. Same model families, grids, random state, fold counts, and bootstrap procedure as the original scripts.

**Exact manuscript location changed:** §2.2 (states the actual implemented rule and discloses the leakage), new §2.5.1 (sensitivity methodology), §3.3 (results), §4.6 Limitations.

**Actual numerical result:** LOCO AUC under strict training-only feature selection changed by at most 0.066 in either direction (largest: Kazakhstan LightGBM 0.591→0.525, Δ=−0.066; Kazakhstan LogReg 0.564→0.609, Δ=+0.045). Retained genus count under training-only selection ranged from 150 (Kazakhstan excluded from feature selection during its own hold-out) to 373, versus 396 globally. Within-cohort AUC moved by −0.083 to +0.038. Full results in `results/tables/training_only_feature_sensitivity_summary.csv` and Supplementary Table S4.

**What conclusion changed:** None of the paper's qualitative conclusions changed — no cohort–model combination flipped between "near chance," "intermediate," and "robust" classifications. We now report this as a tested, not assumed, robustness property, and we explicitly acknowledge the global design as a real methodological limitation that should not be repeated as a design choice in future work, even though it did not distort the magnitude of this particular finding.

## Concern #2

> The batch-correction analysis uses held-out disease labels during ComBat-seq/MMUPHin correction. They argue that this cannot estimate prospective external-validation performance and that corrected within-cohort AUC cannot establish preservation of biological signal.

**We agree with both halves of this concern**, and the second half — which our own pre-audit had initially flagged as the more serious, previously-undisclosed issue — turned out to matter more than we expected.

**Exact analysis/code change:** New scripts `scripts/10_batch_correction_label_blind.R` (ComBat-seq with `group=NULL, full_mod=FALSE`; MMUPHin with `covariates=NULL` and diagnosis entirely absent from the metadata object — confirmed by the R console's own "Using null model in ComBat-seq. Adjusting for 0 covariate(s)" message) and `scripts/11_corrected_generalization_label_blind.py` (identical grids/random_state/folds/bootstrap to the original `07_corrected_generalization.py`). We now distinguish, and report separately:

1. **Uncorrected LOCO** — genuine held-out-cohort evaluation, no batch-adjustment use of target information at all.
2. **Label-blind transductive adjustment** (primary) — target cohort membership and feature values are used (both methods estimate batch effects jointly across all samples in a batch), but target diagnosis is never used.
3. **Label-informed transductive adjustment** (exploratory/oracle-style only) — target features AND target diagnoses are both used.

We do not claim either transductive design (2 or 3) estimates prospective deployment performance; that claim was never appropriate for either, and we say so explicitly in §2.7 and §4.6.

**Exact manuscript location changed:** §2.7 (full rewrite, both designs described precisely), §3.5 (full rewrite — the label-blind result is now presented as primary, the label-informed result as an explicitly-labeled exploratory sensitivity), §4.2 (the "ComBat-seq substantially worsens generalization" mechanistic claim is withdrawn), §4.6 Limitations, new Supplementary Table S5, new Supplementary Figure S5.

**Actual numerical result — this is the most consequential change in this round.** Under label-blind correction, mean LOCO AUC changed by no more than 0.007 relative to uncorrected, for either method or model (e.g., logistic regression: uncorrected 0.640, ComBat-seq label-blind 0.634, MMUPHin label-blind 0.639). No cohort collapsed. Under the original label-informed design, the same comparison had shown ComBat-seq reducing mean logistic-regression LOCO AUC to 0.493, with Kazakhstan collapsing to AUC=0.308. Repeating the *identical* comparison — same cohorts, same raw features, same downstream classifiers — with only the label information removed from the correction step reproduces Kazakhstan at AUC=0.560, essentially matching its uncorrected value of 0.564.

**What conclusion changed:** We no longer state the specific mechanistic claim that "ComBat-seq substantially worsens cross-cohort generalization" — that result was driven in large part by the label-informed design itself, not by an intrinsic property of ComBat-seq's negative-binomial framework applied to compositional 16S data. We similarly withdraw the earlier inference that "within-cohort AUC preservation rules out indiscriminate signal removal," because that inference used the label-informed comparison, which is confounded by the correction's own label-preservation mechanism (`full_mod=TRUE`/`covariates="diagnosis"`). The label-blind within-cohort comparison, which is unconfounded, does support a similar descriptive conclusion (Supplementary Table S5), but we no longer claim this as strong biological evidence beyond the observed AUC values. What survives, and what we now present as the paper's primary batch-correction finding, is narrower and more defensible: under a fair, label-blind evaluation, neither method recovered cross-cohort transferability — it left performance essentially unchanged rather than either fixing or catastrophically breaking it.

## Concern #3

> SHAP direction is currently defined using mean signed SHAP. For LinearExplainer, this sign depends on the coefficient AND the evaluation-background feature-mean difference, so it is not an appropriate definition of whether higher feature abundance pushes predictions toward AD vs CN across cohorts. They request an appropriate direction definition and stability assessment.

**We agree.** Mean signed SHAP is no longer used anywhere in this paper as a direction statistic — we replaced it with a coefficient-based definition and a pre-specified stability assessment, and found a concrete illustration of why the change was necessary while implementing it.

**Exact analysis/code change:** `scripts/08_shap_taxa_comparison.py` now records each outer fold's fitted logistic-regression coefficient per (cohort, taxon) (`COEF_ROWS`), and defines direction from a coefficient-sign-stability screen, specified before any results were examined: a genus's direction in a cohort is "stable" (positive or negative) if the coefficient carries that sign in ≥8 of the 10 outer folds; exact-zero coefficients count toward neither direction (`build_coefficient_stability_table` → `results/tables/logreg_coefficient_stability.csv`). A genus meets the cross-cohort screen if: (a) it is in the top-20 OOF mean-|SHAP| ranking in ≥2 cohorts, (b) it has a stable positive coefficient in ≥1 of those cohorts, (c) it has a stable negative coefficient in ≥1 other (`build_stable_directional_flips` → `results/tables/logreg_directional_flips_stable.csv`). We describe this explicitly in the manuscript as a **descriptive screen, not a formal hypothesis test**: the 10 outer-CV folds share substantially overlapping training data (each fold's training set is 9/10 of the same cohort), so fold-level coefficient signs are not independent statistical replications, and we do not assign multiplicity-adjusted p-values to individual taxa.

**For LightGBM, the directional-flip inference remains withdrawn.** No coefficient-like global direction exists for a tree ensemble, and SHAP–feature relationships may be nonlinear/non-monotonic, so no replacement scalar direction statistic was invented. LightGBM retains OOF mean-|SHAP| feature importance, top-feature overlap, and Jaccard analysis only. `plot_loco_direction()` was removed entirely (for both models): LOCO SHAP's background (training cohorts) and evaluation set (held-out cohort) are systematically different populations by construction, so LOCO SHAP sign is confounded with the raw cross-cohort compositional difference PERMANOVA quantifies, independent of anything the model learned. LOCO SHAP *importance* (magnitude) is retained and unaffected.

**Figure 6 is now built entirely from the coefficient data, with feature importance and direction visually separated.** Panel A shows OOF mean-|SHAP| feature importance only — dot size reflects magnitude, and no color, star, or highlight encodes direction. Panel B is a coefficient grid: rows are the eight genera meeting the stability screen, columns are the four cohorts, cell color/value is the median fitted coefficient across the 10 outer folds, cell text gives the fold count backing that direction (e.g., "10/10 +"), and a black border marks cells meeting the ≥8/10 criterion. This also resolves a display inconsistency an earlier draft had: because Panel A previously used a different taxa pool than Panel B, only 5 of the 8 screened genera appeared starred there; separating importance (Panel A) from direction (Panel B) removes that mismatch, since Panel A no longer attempts to show direction at all.

**Exact manuscript location changed:** §2.8 (full rewrite, including an explicit descriptive-vs-hypothesis-test statement), §3.6 (full rewrite), §4.4 (full rewrite), §4.6 Limitations, Figure 6 (regenerated per above), Supplementary Figure S2 (LightGBM bars changed to a neutral color, removing the same invalid coloring), Supplementary Figures S3a/S3b (LOCO SHAP direction) replaced with an explicit removal notice, new Supplementary Table S6.

**Actual numerical result:** eight genera meet the descriptive coefficient-sign-stability screen for logistic regression (down from the old, invalid mean-signed-SHAP count of 12): *Agathobacter, Bifidobacterium, Coprococcus, Dorea, Lactobacillus, NK4A214 group, Romboutsia, Ruminococcus gnavus group*. We verified the underlying OOF SHAP computation is byte-identical to before this fix (`git diff` on the pre-existing SHAP importance/overlap tables shows zero difference) — only the direction/flip interpretation changed.

**A concrete illustration we did not expect, and report in full:** while writing the *Akkermansia* discussion, we checked its actual coefficient-stability data before writing the prose rather than assuming the old mean-SHAP framing carried over, and found *Akkermansia*'s fitted coefficient is **stable and positive in all four cohorts** (10/10 outer folds each) — it does not meet the screen at all, even though its pooled mean SHAP value does appear to reverse sign across the same four cohorts under the old statistic. The same check caught a second, unrelated error in an earlier pass of this rewrite: we had described *Lactobacillus* as splitting cleanly along a Chinese-cohorts-versus-Kazakhstan line, but its actual per-fold data shows it is stable-negative in Zhuang 2018 only and stable-positive in the other three cohorts (Ling 2020, Zhu 2022, and Kazakhstan). We corrected the manuscript to report this accurately and moved the "cleanest population-level split" example to *Romboutsia*, which does show a stable-negative-in-all-three-Chinese-cohorts / stable-positive-in-Kazakhstan pattern.

**What conclusion changed:** the flip count drops from 12 (logistic regression, invalid statistic) / 12 (LightGBM, invalid statistic, now withdrawn) to 8 (logistic regression, coefficient-stability screen) / none (LightGBM). *Akkermansia*, previously described as a flip taxon, is now understood to have a stable, non-flipping association under the fitted model. The population-interpretable example we highlight is now *Romboutsia* (clean Chinese-cohorts-vs-Kazakhstan split); *Lactobacillus* still meets the screen but with a more complex pattern that we report as observed rather than fitting to a simpler narrative.

## Concern #4

> The Jaccard null must mirror the reported statistic. The observed statistic is the mean of the six pairwise overlaps among four cohorts, whereas the current null appears to generate only two random sets per replicate.

**We agree; this was confirmed exactly as described and reversed part of our reported significance conclusion.**

**Exact analysis/code change:** `scripts/08_shap_taxa_comparison.py`'s `jaccard_null_distribution`/`compute_jaccard_null_baseline` (which drew two random sets and computed one pairwise Jaccard per replicate) replaced with `four_set_null_distribution`/`compute_jaccard_null_baseline_corrected`: each of 100,000 replicates now draws four independent random top-N gene sets from the 396-genus pool and averages the same six unique pairwise Jaccards among them — the identical statistic-construction procedure as the observed value (verified in code with an explicit `assert len(pairwise) == 6`). Computed at N=10, 20 (primary), and 50. Empirical one-sided p = (1 + #{null ≥ observed}) / (n_perm + 1).

**Exact manuscript location changed:** §2.8, §3.6, Abstract, Conclusion, new Supplementary Table S7, Figure 6 caption, Supplementary Figure S2 caption.

**Actual numerical result:**

| Model | N | Observed (6-pair mean) | Matched null mean [95% CI] | Empirical p |
|---|---|---|---|---|
| LogReg | 20 (primary) | 0.135 | 0.027 [0.009, 0.049] | <0.0001 |
| LightGBM | 20 (primary) | 0.058 | 0.027 [0.009, 0.049] | **0.0048** |
| LightGBM | 10 | 0.018 | 0.013 [0.000, 0.036] | 0.449 (not significant) |

**What conclusion changed:** the original manuscript reported LightGBM's top-20 overlap as "within the random baseline" (p=0.068 under the old, mismatched null). Under the corrected, matched null, it is **statistically significant** (p=0.0048) — a reversal in the opposite direction from concern #2's finding. We report this honestly: LightGBM's overlap is real but small in magnitude and genuinely N-dependent (not significant at N=10), so we describe it in the manuscript as "greater-than-random overlap was detected, though small in magnitude and dependent on the choice of N" rather than either the old "no shared features" framing or an overstated "confirmed overlap" framing. Logistic regression's overlap was already significant under the old null and remains significant — more strongly so — under the corrected one at all three N values tested.

## Concern #5

> PERMANOVA demonstrates strong cohort-associated heterogeneity but does not establish that this is why batch correction worsened performance. Claims must distinguish empirical result from possible explanation.

**We agree**, though on inspection most of the manuscript's PERMANOVA language was already reasonably hedged ("consistent with the interpretation that..."); one Discussion passage blended the empirical finding with the causal hypothesis without a clear sentence-level boundary, and we have now separated them everywhere PERMANOVA is invoked in connection with batch correction.

**Exact analysis/code change:** None — the PERMANOVA analysis itself (`scripts/05_permanova_variance_decomp.R`) is not disputed and was not rerun. We did fix one unrelated, purely cosmetic issue found in the same file: a stale, hardcoded "n=521" console-print label (the actual labeled sample count is 401, used correctly everywhere the number is actually computed) — corrected to "n=401 labeled" with no change to any analysis or result.

**Exact manuscript location changed:** §3.4 (added an explicit sentence stating what PERMANOVA marginal R² values do and do not establish), §3.5 (the sentence connecting the 12-fold disparity to batch correction now explicitly says it "provides context for... but does not by itself establish... nor does it explain" the specific correction pattern), §4.2 (restructured into an explicit "Empirical result" / "Hypothesis, clearly flagged as such" structure; the ComBat-seq mechanistic claim withdrawn under concern #2 is folded in here since both changes concern the same passage).

**Actual numerical result:** unchanged — R²=0.193 (5-cohort), R²=0.172 (cohort, marginal, 4-cohort model), R²=0.014 (diagnosis, marginal). These numbers were never in dispute.

**What conclusion changed:** PERMANOVA is now presented purely as descriptive evidence of cohort-associated heterogeneity (an empirical fact about this dataset), not as a mechanistic explanation of why batch-adjustment performance changed in a particular direction. The specific pattern we observed — label-blind correction flat, label-informed correction severely disruptive for some cohorts — is now attributed to the transductive/label-informed design itself (concern #2's finding), not to the general cohort/diagnosis variance disparity, and the manuscript says so explicitly.
